# Key Capture Notes

For validated 4.2.0.12, use `Get-WeChat4ConfigKeys.ps1`: bounded, read-only
Config.Cipher traversal, XOR decoding and file-only candidate output. See
[4.2 migration notes](WECHAT_4_2.md) for evidence, limits and attribution.
No new debugger RVA is asserted.

The debugger workflow below is the historical **4.1.11.54** path.

## Breakpoint target

```text
Module: Weixin.dll
RVA:    0x5D79A0
Name:   WCDB_Database_setCipherKey
```

## Debug API flow

1. Launch `Weixin.exe` with `DEBUG_ONLY_THIS_PROCESS`.
2. Call `DebugSetProcessKillOnExit(false)`.
3. Wait for `LOAD_DLL_DEBUG_EVENT` for `Weixin.dll`.
4. Compute `runtime_base + 0x5D79A0`.
5. Save the original byte and write `0xCC`.
6. On breakpoint:
   - read thread context;
   - read key object pointer from `RDX`;
   - read buffer pointer at `RDX + 0x08`;
   - read buffer length at `RDX + 0x10`;
   - collect a candidate key;
   - restore the original byte;
   - set trap flag and single-step.
7. On single-step:
   - clear trap flag;
   - reinsert the breakpoint if more candidates are needed.
8. Detach.

The single-step exception generated by the tool must be continued with `DBG_CONTINUE`. Passing it back as unhandled can destabilize the debuggee.

## SQLCipher verification

Captured bytes are candidates, not proof. The exporter validates candidates by trying:

```text
raw64
raw96
asciihex
hexkey
```

with compatibility 3/4 applied after the key. Each database independently
selects a candidate after a schema read; modern raw candidates first receive a
SQLCipher 4 page-HMAC check. Decrypted databases must pass `quick_check`.
Probe and export return nonzero if any selected database fails.
